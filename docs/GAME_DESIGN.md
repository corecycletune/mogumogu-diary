# もぐもぐ日記 ゲーム仕様（決定事項）

更新：2026-10-11。実装状況は README の「ゲーム試作」を参照。ここに記した内容が今後のデザイン基準。変更する場合は相談する。

## 目的と設計原則
- 食事を記録した習慣に報酬を与える。食べる速さ・時間の長短で有利・不利を付けない。
- 家族3プロフィール「いちか / じゅんちゃん / さとばぁば」それぞれ独立したゲーム進行を持つ。
- 毎日1回の**無料ガチャ**を用意。通常の食事記録や連続記録・ログインでコインや追加ガチャ券を付与する。食べ過ぎや頻回の間食を促進する設計にしない。1日3食を上限とした食事記録報酬。
- 収集するものは「食べ物を基本に、偉人・芸術・歴史上の逸話や象徴を絡めたキャラクター」。
- キャラクターデザインは**混合型**。食べ物に人格・衣装をつける／人物風の造形に食べ物の意匠を持たせる／両者中間、をキャラごとに選ぶ。
- 偉人の「好物」と断定する必要はない。ニュートンとりんごのように、歴史的な逸話・象徴・芸術作品・ゆかりでもよい。**史実と創作を区別**し、図鑑説明に関係の種類と出典を後から持たせられる設計とする。
- **日本の芸術家を特に厚く**収録する。海外の芸術家やその他の偉人も扱う。背景に偉人情報を詰め込まず、図鑑の説明側に記載。
- 「オムライス」はいちかの好物のため、特別シリーズとして**RからSSRまで多数**のバリエーションを用意。必ずSSRの「いちかのオムライス」を含める。

## 5段階レアリティと非公開UR
- N / R / SR / SSR / UR。
- 参照する基本評価軸：①現実の食品の希少性、②子どもの好物としての特別感、③偉人・芸術・歴史との関連。ただしゲームとして魅力的な特例は認める。
- URは**存在を原則公表しない隠し要素**。未所持の図鑑にはURの名前・シルエット・総数・排出率・レア表記を出さない。
- 1回ごと独立抽選の初期排出率（暫定確定）：N 72%、R 20%、SR 6%、SSR 1.75%、UR 0.25%。500回当たりURの期待値1.25枚（保証なし）。すべての結果を当選率順に引き、レア内は等確率でキャラを選ぶ。
- 子どもに射幸性を煽る購入要素は作らない。**課金は実装しない**。現段階での天井／救済なし。URの存在を示唆するカウントダウンなどもなし。
- 重複したキャラは**同じキャラを成長・レベルアップ**させる。レアリティ自体は上昇させない。表示・フレーム・演出の追加拡張を想定する。

## カードの背景と量産性
- キャラ画像と背景を別アセットとして管理。キャラ×背景の全組み合わせ画像を事前生成しない。
- **N→R→SR→SSR→（隠し）UR**の順に、色数・反射・模様・フレームの豪華さを増す。レアごとに共通のルールと、各レア内に複数の背景パターンを設定。
- N：単色〜2色／ドット・チェック・ストライプ・雲。
- R：アクセントカラー／キャンディ・フルーツ・カフェ・ピクニック。
- SR：ホログラム・放射光／虹ホロ・和柄・音符・絵具。
- SSR：箔押し風の二重装飾・オーラ／王冠・宮殿・芸術額縁・巻物。
- UR：オーロラ・多層光彩・特別枠／神話・時空・金箔虹・秘宝。
- SSR/URの一部は背景もキャラ専用の**ユニークカード**可。
- 伝統的トレーディングカードのキラキラ感やホログラムの楽しさに着想を得つつ、他社カードの絵柄・レイアウト・ロゴ・固有装飾をコピーしない。
- 描画はまず「背景CSSレイヤー + 絵文字による暫定キャラ + レア枠」で実装し、後に個別のオリジナルキャラクター画像を差し替え。図鑑の大量表示が重くならないよう共通CSS背景のみを再利用する。

## 初期ゲーム運用
- 1日1回無料ガチャ（同日の再利用不可）。同じ端末で日付が変われば新しい無料枠。
- ログインボーナス+10コイン（同日1回）。
- クラウド保存された食事記録から1日最大3回まで加算：最初の食事+20、次の2食各+10。おやつはこの対象外。記録時間の大小によってコイン量は変わらない。
- 3日連続記録+30コイン、7日+ガチャ券1枚、14日+2枚、30日+3枚（初期値）。
- 100コインで追加ガチャ1回、またはガチャ券を1枚消費。
- レベルは重複枚数の閾値により1〜5。獲得枚数1/2/4/7/11でLv.1/2/3/4/5。カードに重複枚数も表示する。
- ガチャと図鑑、ゲーム状態はFirebaseの各プロフィール専用データに保存。未接続時にはクラウド抽選を行わず誤認する「同期済み」表示をしない。
- 初期コンテンツは日本の芸術家モチーフ、オムライスシリーズを優先し、他の食品や世界の偉人と合わせて最低50種のデータマスタを目標にする。

## Firestore / セキュリティ上の制約
- データは `families/{familyId}/games/{profile}` に保存し、書き込みは本人の匿名Authで登録したプロフィールに制限。
- 書き込み時の競合はFirestoreトランザクションで処理。同日無料ガチャ・残高・同一キャラの重複加算が複数端末操作で失われないようにする。
- ゲームは端末配布型PWA。キャラクターマスタ・確率・抽選コードがクライアントへ配信されるため、**技術者に対しURを秘密にしたり不正抽選を完全防止することはできない**。本当の秘匿・改ざん防止が必要になったらCloud Functions等のサーバー側抽選とルール改修を行う。
- Firestoreルールを更新後、Firebase Consoleで手動「公開」が必要。GitHubにrulesファイルを置いただけでは運用環境に反映されない。
