## 3. レアリティと抽選仕様

| レア度 | 排出率 | 作画・豪華さの基準 |
|---|---:|---|
| **N** | **72%** | 高品質なキャライラスト＋ごく簡素な紙風**背景画像**・細枠、ホロなし |
| **R** | **20%** | Nより明確に華やかな色・模様・小さな装飾、ただし**派手すぎない**。基本ホロなし |
| **SR** | **6%** | キャラの魅力を維持しつつ装飾追加、薄いパール・軽いホロ反射 |
| **SSR** | **1.75%** | **圧倒的に豪華**。専用の細密イラスト、**派手な極彩色**・密な金装飾・固有の背景とフレーム・強い虹色ホログラム。**個別フルアートを採用** |
| **UR** | **0.25%** | **隠し要素・別格の専用アート**。**かっこいい宇宙的な専用アート。構図はシンプルで余白を活かし、SSRより希少で豪華**な素材感・特別演出・背景・フレーム。**フルアート生成可** |

- レアリティは**N → R → SR → SSR → UR**の順に明確に豪華になる。**NとRの差**は色・背景とフレームの工夫で読み取れるようにし、SRから光沢が分かるようにする。
- 実際の食品の珍しさ、子どもにとっての好物度、偉人との関係の特別さをレア評価の参考にするが、ゲームとしての演出上の例外を認める。
- URは**存在を原則秘密にする**。未所持状態の通常図鑑・公開UIで名前・シルエット・総数・排出率・存在を明かさない。開発用プレビューのみ例外。
- URの期待値は**500回で1.25枚**。独立抽選で保証はなく、現段階で天井・救済は設けない。全レア内のキャラは現行仕様では等確率。
- 公開リポジトリにキャラマスタ・抽選コードが含まれる限り、**技術的な完全秘匿ではない**。必要なら後にサーバー抽選を検討する。

## 4. **最重要：カードの制作方式（美術仕様と実装仕様を混同しない）**

### 4.1 N・R・SR：高品質キャラ画像＋共通部品の合成

**キャラクター本体は、高品質で個性のある独立したイラストを画像生成等で制作し、透過PNG／WebPなどの画像素材として扱う。**

- 食べ物・人物の要素、表情、衣装、固有のポーズ、色、陰影、質感まで**キャラごとに描き込む**。
- **簡易SVGをプログラムで量産したキャラクター、共通素体の色替え・帽子替え、絵文字を最終イラストとして採用しない。**
- SVGを使用するのは原則、**フレーム・幾何模様・飾り・UI効果**。**背景SVGは使用しない。**ベクター形式そのものを禁止するわけではないが、簡易SVGキャラは不合格。完成イラストと同等の品質があり個別承認された場合だけ例外とする。
- **「5レイヤーで作る」は、カードをどう合成するかの技術仕様であって、キャラクターをSVGで描く指示ではない。** この区別を守る。
- 共通化するのは**背景や装飾などの部品**。キャラの個性を犠牲にして制作コストだけを下げない。

**推奨レイヤー（背面 → 前面）**

1. **背景**：**N/R/SR/SSR/URの5段階で別々の背景ラスタ画像（WebP/PNG）を用意する。SVGで背景を制作・保管しない。** Nは控えめ、Rは少し華やか、SRは物語性、SSRは豪華、URは別格。キャラ・文字・額縁を焼き込まず、共通再利用可能な背景画像だけを制作。
2. **ホロ／印刷質感**：背景の無地・余白部分を光らせる。キャラクター本体を白く覆わない。N・Rは原則なし、SRは弱め。
3. **下フレーム SVG**：輪郭・基礎額縁・装飾の土台。
4. **キャラクター透過PNG／WebP**：カードの主役となる描き込まれたイラスト。
5. **上フレーム SVG**：キャラの手前に重なる角飾り・箔・リボン等。主役を隠しすぎない。
6. **HTML／CSSテキスト**：キャラ名・レア度・レベル・種別など。後から変更できるよう画像とは分離。

この5つの絵作りレイヤー＋文字UIを、実際の**Webアプリ上で合成**する。単に各レイヤーの完成イメージを画像生成して見せるだけでは「実装」とは言わない。

### 4.2 SSR・UR：制作点数が少ないためフルアートを許可

- **SSRは現在11種類、URは3種類**の初期マスタ。ここはパーツ量産にこだわらず、**高精細で豪華な個別生成イラスト／カード全体のフルアート**を正式に認める。
- **SSRの品質基準は、ユーザー提示の「ゴッホのひまわりパン」の豪華なキラカード参考画像程度。** 豊かな陰影、緻密な造形、ひまわりや金箔・宝石・リボン・背景の情報量、強いホログラムが見て取れること。従来の単純なSVGキャラ＋斜め線背景は不合格。
- SSRは**かなり派手でよい**。Rから派手にしすぎず、SSRに明確な格上感を持たせる。
- URはSSRを超える専用表現を許すが、**未発見状態では存在を示唆しない**。
- フルアート画像を使う場合も、可能な限り**カード名・所持レベル・レア度などの情報をアプリ側で保持**する。フレームや背景まで画像化してよく、SSR/URだけ5レイヤーを強制しない。
- フルアート使用とレイヤー構造の共存が可能な設計にする。今後の差し替えを容易にするためカードIDとゲームデータは維持する。

### 4.3 ホロの意味

- ユーザーが求める「ホロ」は、単に**一瞬キランと走る反射アニメーション**だけではない。
- **背景の無地・余白に、現物のトレーディングカードのような細かなラメ・多層反射・虹色箔・光の粒が見える状態**を指す。必要なら画像化したホロ模様や生成フルアートを使う。
- CSS・SVG・透明素材は手段。**安っぽい単純な線・均一なキラ粒だけで完成としない**。
- SSR/URではホロの華やかさを十分確保する。キャラの表情や造形を光で潰さない。

### 4.4 現行のSSR・UR生成ルール（2026-10-12確定）

**今後のSSR・UR制作は本節を優先する。下の過去の試作経過にある「8頭身必須」「惑星だけの物体」「写実的な探検家」は現行の制作基準ではない。**

| 項目 | SSR | UR |
|---|---|---|
| 印象 | 派手派手・極彩色、豊かな装飾と物語 | 宇宙的でかっこよく、SSRより希少で豪華 |
| シリーズ共通の描画 | 柔らかなアニメ／絵画的な顔・陰影、食べ物・衣装・小物の細密な描き込み | 同じ描画の系統。SSR「クリムトの金色はちみつ」を顔・衣装・陰影・細かさの基準にする |
| 画面と色 | 宝石色、多彩な背景、密な専用額縁、金装飾 | 深い宇宙の色と余白を基礎に、土星は金／アンバー、海王星は青／白金など抑えた色系統。色調をSSRと同じ明るい金の庭へ変えない |
| キャラのテーマ | 食べ物×芸術・歴史・文化、実メニューのオムライス等 | **惑星×連想する食べ物×関連する偉人または探査機**の3モチーフを衣装・装備・表情・ポーズに統合 |
| 人物の描き方 | テーマに応じた食べ物型・人物型・混合型 | **全キャラ擬人化**。かっこよさと同じシリーズの親和性を優先し、厳密な8頭身を必須にしない。写実的な成人モデルや硬いメカ主体の別シリーズへ寄せない |
| 豪華さの差 | 彩色と情報量、豊かな背景・額縁 | 厚みのある押し箔、浮き彫りの輪郭・環・額縁、希少な金属・宝石の精密な質感、鋭い反射で上位感を作る |

制作手順と不変条件：

1. 既存のカードマスタ・SSOT・現在の実装を確認し、カードごとの主題と、同じシリーズの参考画像を用意する。関連する偉人や探査機の事実は一次資料で確認し、食品との連想や擬人化は創作として区別する。
2. **1カードごとに独立した4:5の不透明なフルアート**を画像生成する。背景・専用額縁・キャラを一体にしてよい。共通フレームの単なる色替え、簡易SVG、一覧画像の切り出しで代用しない。
3. URはSSR参考画像を描画の基準として与えつつ、URの宇宙の色調・余白・箔押しを維持する。8頭身を機械的に守るためにシリーズの絵柄を失わない。
4. 箔押しの静的な素材感は画像に描き込んでよいが、**ホロ／スペクトル反射は独立レイヤー**で必ず実装する。顔・料理・主要シルエットを白く覆わず、主に外周・背景で反射させる。動きを減らす設定に対応する。
5. カード名・レア度・Lv・所持枚数・説明は画像へ焼き込まず、アプリ側のHTMLに保持する。画像はWebPで `assets/cards/full-art/<card_id>.webp` に保存し、`CARD_LAYER_MANIFEST.fullArt` へ紐付ける。
6. 図鑑・ガチャ・開発用比較で同じ画像とホロを使う。キャッシュ世代・画像URLの版を更新し、PC／スマホ幅、全レア度比較、画像読込・JS・キャッシュ・所持データの不変を確認して公開・GitHub再取得検証まで行う。
7. 既存ID・レア度・排出率・所持データを維持する。未所持URは通常図鑑に表示せず、全レア度比較は開発画面限定。今回の採用URは試作2枚で、残りURの量産や全シリーズの最終承認を意味しない。

## 5. 品質確認・実装時の必須手順

1. レア度ごとの**美術基準**を最初に確認する（NとRの差、SRの中間感、SSRの圧倒的な豪華さ、URの別格感）。
2. **最初にN・R・SRの高品質な透過キャラ素材を確保する。** 枠やホロだけ完成していてもキャラが簡易SVGなら不合格。
3. アプリ側の背景／下枠／キャラ／上枠／ホロを**ブラウザで実際に合成**。SSR/URの場合は合意したフルアート方式でも可。
4. **画面上の実物**で確認する。比較画像を生成して終わらない。PC/スマホ表示、図鑑一覧と拡大表示、Rが派手すぎないか、SSRが十分豪華かを確認する。
5. **ユーザーが品質を了承してから量産**する。承認済み基準と違う作画手段・品質への変更は先に相談する。
6. 試作と本番・承認済みと未承認を明記する。検証用カードの存在だけで「62枚完成」と表現しない。

## 10. N・R・SRフレーム・量産設計（2026-10-12、デザイン方針確定）

> **決定：デザインテーマ別の組み合わせ方式（A案）を採用。**
> 本節は**これから制作する素材と実装の仕様**であり、下記の新規フレーム素材・自動組み合わせロジックがすでに実装されたことを意味しない。

### 10.1 基本原則

- N/R/SR は **背景ラスタ画像 × 下・上フレームSVG × 高品質透過キャラ画像 × レアリティ内の演出** を独立部品として合成する量産方式を採用する。
- **豪華さはレアリティ間で差を付け、デザインの多様性はレアリティ内で増やす。** 同一レアリティ内の異なるテーマ・色・構図で、価値の上下を意図的に作らない。
- **N < R < SR << SSR** の視覚序列を必ず守る。背景とフレームと効果を全て合わせた状態で判定する。SRの最も装飾的な組み合わせでも、SSRの特別感を超えない。
- **SVGで制作してよいのはフレーム・装飾・幾何模様・UI効果。** 背景は PNG/WebP のまま、キャラは高品質な個別透過 PNG/WebP のまま。簡易SVGキャラの再導入や背景SVG化は禁止。
- SSR/URは量産用フレーム共通化の対象外。背景・フレーム・キャラを統合した専用フルアート画像を許可し、名前・レベル・レア度等の動的文字はアプリ管理を原則とする。

### 10.2 初期フレームテンプレート：計8セット（制作目標）

| レア度 | フレームID（設計上の識別子） | デザインテーマ | 装飾の限度 |
|---|---|---|---|
| N | \`n-paper\` | 紙・素朴・ニュートラル | 細枠、無彩色〜淡色。ホロ・金属箔・宝石なし |
| N | \`n-corner\` | 控えめな角飾り・手帳 | 小さい角模様。細枠を維持 |
| R | \`r-botanical\` | 植物・自然 | 葉や蔓など小さな装飾。ホロなし |
| R | \`r-geometric\` | 幾何学・科学・モダン | 規則模様と彩色。金属箔の印象を強くしない |
| R | \`r-antique\` | 古典・アンティーク | 控えめな古典装飾。大きな宝石・強い光沢なし |
| SR | \`sr-silverwork\` | 銀細工・学術・星 | 細い金属表現と控えめな真珠光沢 |
| SR | \`sr-wagara\` | 和風・伝統装飾 | 和柄・組紐・蒔絵風意匠を抑制的に使用 |

### 10.3 背景・演出との組み合わせと拡張

| レア度 | 現在の背景アセット | 将来の背景設計 | フレーム数（初期目標） | 演出の上限 |
|---|---|---|---:|---|
| N | 既存1種（維持） | 淡い紙・室内などの控えめな**複数の造形テーマ**へ拡張。まず3テーマを制作目標とする | 2 | 演出なし（固定） |
| R | 現行7色（同一基礎テーマの色違い） | 7色を保ち、自然・幾何・古典など**模様・構図が異なる背景テーマ**を順次増やす | 3 | マット / 軽いサテン印象。ホログラムなし |
| SR | 現行紺基調7色（同一基礎テーマの色違い） | 7色を保ち、天文・和風・幻想など**模様・構図が異なる背景テーマ**を順次増やす | 3 | 弱いパール / ごく弱い箔反射。密な虹色ラメは使わない |

- 色違い・フレーム種類・演出の組み合わせ数は上限や保証数ではない。**実際の採用組み合わせは品質とテーマ適合を優先する**。

### 10.4 テーマ別の組み合わせルール

1. 各背景・フレーム・キャラに、\`rarity\`、\`themeTags\`（例：\`nature\`, \`science\`, \`japanese\`, \`classic\`, \`fantasy\`, \`neutral\`）、必要なら \`palette\`・\`compatibility\`・\`exclusions\` を持てるようにする。
2. **同じレアリティ内**で、背景とフレームのテーマ相性を第一に評価する。キャラクターの世界観とも大きく矛盾しない組み合わせを選ぶ。テーマを跨ぐ例外は個別指定で可能とする。
3. タグだけで全組み合わせを許容しない。低コントラストで輪郭が消える色、キャラを隠す装飾、背景と金属色の衝突、物語上不自然な組み合わせは除外する。
4. 同じカードIDの組み合わせは**端末・ガチャ・再表示を跨いで固定**する。現在の背景色割当を不用意に変更しない。将来のテーマ追加で既存カードが自動的に別デザインになる挙動は避け、再割当は明示した改版時のみ行う。
5. 組み合わせは**明示的なカード別指定を優先**し、未指定カードに限りテーマ適合する候補から決定的に選択する。組み合わせ候補の一覧と除外理由を開発画面で確認可能とする。
6. 絵を描き直さず組み合わせを増やすための方式であり、完成キャラ画像の品質基準を緩めない。未制作キャラをSVGや絵文字で埋めない。

### 10.5 上下SVGフレームの技術仕様

- 2枚のフレームは**同じサイズ・座標系・縦横比**を使う。新規テンプレートの標準 \`viewBox="0 0 420 525"\`（4:5）。既存の4:5 SVGは流用時に座標を確認し、安易な引き伸ばしで装飾比率が崩れないようにする。
- 置き場は原則 \`assets/cards/frames/base/<frame-id>.svg\` と \`assets/cards/frames/top/<frame-id>.svg\`。共通の \`frameId\` で下・上を1セットとして特定する。
- 下フレームは輪郭・下敷き・基礎装飾、上フレームはキャラクターの手前に重なる小さな角飾り・リボン等。**上フレーム中央に不透明な大面積を置かず**、顔・料理・主要モチーフを隠さない。
- SVGは原則**透明な装飾素材**とする。内部に背景絵を内包しない。文字・キャラ・外部画像の埋め込みをしない。
- **レンダリング順は背景 → ホロ/材質演出 → 下フレーム → 透過キャラ → 上フレーム → 文字UI。** 光学演出はキャラ本体を白く覆わない。UIのレア度バッジや名前と干渉しない余白を残す。
- モバイルの図鑑サムネイル表示で、細線が潰れないか・文字UIと重ならないかを確認する。実際のWebアプリで組み合わせ表示して判断し、SVG単体の見た目だけで合格としない。
- 演出は別ID・別パラメータとして管理し、フレームの形状・色替え・アニメーションを結び付けすぎない。アクセシビリティ設定で動きを減らしても識別可能にする。

## 11. SSR専用フルアートとURとの差（2026-10-12、ユーザー指定）

### 11.1 現行の制作方針

- **SSR：派手派手・極彩色。** 食べ物×芸術・文化の各テーマを、鮮やかな多色、豊かな物語、密な装飾、独自の額縁・背景・キャラを一体にした専用絵で表す。11種類をそれぞれ独立して画像生成する。共通フレームの色替えで量産しない。
- **UR：かっこよく、宇宙的、シンプルな構図。** 色数・装飾数をただ増やしてSSRを超えるのではなく、深い空間、余白、精密な造形、希少な金属・宝石の質感、鋭く制御された光で上位の豪華さを表す。SSRよりレアで豪華という序列を維持する。
- SSRで深い宇宙、黒い余白、孤立した天体・軌道を主要な共通テーマとして使わず、URのために視覚的な差を残す。
- 今回の制作対象は**SSR全11枚**。URの新規画像制作は次工程。この方針確定だけでUR制作済み・SSRとの実物比較が完了したと報告しない。
- オムライスは実メニュー方針を維持。`omu_ichika_ssr` はドレスドオムライス、未制作の `omu_royal_ssr` は**オムハヤシ**へ改名し、同じID・レア度のまま制作する。

### 11.2 画像と表示

- SSRは**背景・独自フレーム・キャラを1枚の不透明なラスタ画像**にまとめてよい。標準の表示比率は4:5。保存先は `assets/cards/full-art/<card_id>.webp`。
- 名称、レア度バッジ、Lv、所持枚数、説明は画像へ焼き込まず、アプリのHTMLに保持する。
- **ホロは別レイヤーを必須とする。** 1枚絵の表示の上に独立した虹色箔・微細ラメ・反射レイヤーを合成する。中央のキャラの顔・料理を光で白く覆わない。外周・背景・額縁に寄せたマスクと低い不透明度で保護する。
- 動きを減らす設定では反射アニメーションを停止しても、静的な箔・ラメの質感を残す。
- N/R/SRの画像・背景・フレーム・合成方法、URの既存設定、カードID・排出率・所持データは維持する。旧SSRの独立キャラ・共通部品は参照切替後も履歴・再利用のため無断削除しない。
- 画像生成・WebP化・通常図鑑/ガチャ/開発画面への実装・キャッシュ更新・公開・再取得検証まで一連の作業で行う。画像の制作・実装完了とユーザーによる最終の美術品質承認は区別する。


### 11.3 SSR全11枚の実装記録

- 画像生成ツールで各カードを独立した4:5のフルアートとして制作し、`assets/cards/full-art/` に11枚のWebPを追加。
- `CARD_LAYER_MANIFEST` のSSR11件を `fullArt` 参照へ切替。旧SSRの共通背景・SVGフレームは重ねず、画像内の専用額縁を表示する。旧素材は削除しない。
- 通常の `paintCard()` と開発用レイヤー比較の両方で、1枚絵の上に独立した箔・反射レイヤーを追加。顔・料理の中央を避ける外周マスクを使用する。
- 開発画面にSSR11枚の一覧を追加。絵とホロは切り替えて検証できる。キャッシュは `mogumogu-static-v24`、画像URLは `?v=ssr-full-art-v1`。
- 画像11枚の読込、ホロ11枚・反射11枚、PC・スマホ幅での表示、N/R/SR/URの既存描画とデータ・抽選率の不変を確認する。UR画像はまだ未制作のため、上位感の最終比較はUR試作後に行う。
