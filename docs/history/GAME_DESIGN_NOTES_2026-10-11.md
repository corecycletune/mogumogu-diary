# もぐもぐ日記 ゲーム仕様（決定事項）

更新：2026-10-11。実装状況は README の「ゲーム試作」を参照。ここに記した内容が今後のデザイン基準。変更する場合は相談する。

## 目的と設計原則
- 食事を記録した習慣に報酬を与える。食べる速さ・時間の長短で有利・不利を付けない。
- 家族3プロフィール「いちか / じゅんちゃん / さとばぁば」それぞれ独立したゲーム進行を持つ。
- 毎日1回の**無料ガチャ**を用意。通常の食事記録や連続記録・ログインでコインや追加ガチャ券を付与する。食べ過ぎや頻回の間食を促進する設計にしない。1日3食を上限とした食事記録報酬。
- 収集するものは「食べ物を基本に、偉人・芸術・歴史上の逸話や象徴を絡めたキャラクター」。
- キャラクターデザインは**混合型**。食べ物に人格・衣装をつける／人物風の造形に食べ物の意匠を持たせる／両者中間、をキャラごとに選ぶ。
- 偉人の「好物」と断定する必要はない。ニュートンとりんごのように、歴史的な逸話・象徴・芸術作品・ゆかりでもよい。**史実と創作を区別**し、図鑑説明に関係の種類と出典を後から持たせられる設計とする。
- **日本の芸術家を特に厚く**収録する。海外の芸術家やその他の偉人も扱う。背景に偉人情報を詰め込まず、図鑑の説明側に記載。
- 「オムライス」はいちかの好物のため、特別シリーズとして**RからSSRまで多数**のバリエーションを用意。必ずSSRの「きらめきオムライス姫」を含める。

## 5段階レアリティと非公開UR
- N / R / SR / SSR / UR。
- 参照する基本評価軸：①現実の食品の希少性、②子どもの好物としての特別感、③偉人・芸術・歴史との関連。ただしゲームとして魅力的な特例は認める。
- URは**存在を原則公表しない隠し要素**。未所持の図鑑にはURの名前・シルエット・総数・排出率・レア表記を出さない。
- 1回ごと独立抽選の初期排出率（暫定確定）：N 72%、R 20%、SR 6%、SSR 1.75%、UR 0.25%。500回当たりURの期待値1.25枚（保証なし）。すべての結果を当選率順に引き、レア内は等確率でキャラを選ぶ。
- 子どもに射幸性を煽る購入要素は作らない。**課金は実装しない**。現段階での天井／救済なし。URの存在を示唆するカウントダウンなどもなし。
- 参照モデル：[原神・公式「Standard Wish」提供割合](https://webstatic-sea.hoyoverse.com/genshin/event/e20190909gacha/index.html?gacha_id=fecafa7b6560db5f3182222395d88aaa6aaac1bc&lang=en&region=os_asia)（★5の基礎確率0.600%、★4の基礎確率5.100%、保証あり）など、人気スマホゲームの希少枠設計。もぐもぐ日記は**5段階の独自配分**とし、UR0.25%・天井なしで「500回で期待1.25枚」に合わせる。既存ゲームの排出率をそのままコピーしたものではない。
- 他社ガチャの課金・天井・ピックアップ等の運用上の条件と、当アプリの無料配布条件は異なる。
- 重複したキャラは**同じキャラを成長・レベルアップ**させる。レアリティ自体は上昇させない。表示・フレーム・演出の追加拡張を想定する。

## カードの背景と量産性
- キャラ画像と背景を別アセットとして管理。キャラ×背景の全組み合わせ画像を事前生成しない。
- **N→R→SR→SSR→（隠し）UR**の順に、色数・反射・模様・フレームの豪華さを増す。レアごとに共通のルールと、各レア内に複数の背景パターンを設定。
- N：単色〜2色／ドット・チェック・ストライプ・雲。
- R：アクセントカラー／キャンディ・フルーツ・カフェ・ピクニック。
- SR：ホログラム・放射光／虹ホロ・和柄・音符・絵具。
- SSR：箔押し風の二重装飾・オーラ／王冠・宮殿・芸術額縁・巻物。
- UR：オーロラ・多層光彩・特別枠／神話・時空・金箔虹・秘宝。
- SSR/URの一部は背景もキャラ専用の**ユニークカード**可。
- 伝統的トレーディングカードのキラキラ感やホログラムの楽しさに着想を得つつ、他社カードの絵柄・レイアウト・ロゴ・固有装飾をコピーしない。
- 描画はまず「背景CSSレイヤー + 絵文字による暫定キャラ + レア枠」で実装し、後に個別のオリジナルキャラクター画像を差し替え。図鑑の大量表示が重くならないよう共通CSS背景のみを再利用する。

## 初期ゲーム運用
- 1日1回無料ガチャ（同日の再利用不可）。同じ端末で日付が変われば新しい無料枠。
- ログインボーナス+10コイン（同日1回）。
- クラウド保存された食事記録から1日最大3回まで加算：最初の食事+20、次の2食各+10。おやつはこの対象外。記録時間の大小によってコイン量は変わらない。
- 3日連続記録+30コイン、7日+ガチャ券1枚、14日+2枚、30日+3枚（初期値）。
- 100コインで追加ガチャ1回、またはガチャ券を1枚消費。
- レベルは重複枚数の閾値により1〜5。獲得枚数1/2/4/7/11でLv.1/2/3/4/5。カードに重複枚数も表示する。
- ガチャと図鑑、ゲーム状態はFirebaseの各プロフィール専用データに保存。未接続時にはクラウド抽選を行わず誤認する「同期済み」表示をしない。
- 初期コンテンツは日本の芸術家モチーフ、オムライスシリーズを優先し、他の食品や世界の偉人と合わせて最低50種のデータマスタを目標にする。

## Firestore / セキュリティ上の制約
- データは `families/{familyId}/games/{profile}` に保存し、書き込みは本人の匿名Authで登録したプロフィールに制限。
- 書き込み時の競合はFirestoreトランザクションで処理。同日無料ガチャ・残高・同一キャラの重複加算が複数端末操作で失われないようにする。
- ゲームは端末配布型PWA。キャラクターマスタ・確率・抽選コードがクライアントへ配信されるため、**技術者に対しURを秘密にしたり不正抽選を完全防止することはできない**。本当の秘匿・改ざん防止が必要になったらCloud Functions等のサーバー側抽選とルール改修を行う。
- Firestoreルールを更新後、Firebase Consoleで手動「公開」が必要。GitHubにrulesファイルを置いただけでは運用環境に反映されない。

## 開発用テストガチャ

- **じゅんちゃん専用テストURL** `/p/jun/?dev=1` のみ、ユーザーがON/OFFできるテストモードのUIを配置。ほかの2人には表示しない。
- 抽選を回数無制限でプレビューでき、指定レアの見た目や重複Lv.5まで検証できる。
- テストのカードや報酬はJavaScriptの**メモリ内のみ**。Firestore、食事記録、ゲーム実績、コインを更新しない。OFFで完全リセット。
- この「専用」はURLの表示制御に過ぎず、ユーザー認証による管理者権限を意味しない。
- テストモードと本番ガチャを明確に区別し、テスト結果には未保存であることを明示する。


## 承認済みカードイラストの方向性（2026-10-11）

2026-10-11に、中央絵文字から**オリジナルSVGキャラクター前景の第一版**へ置換した。ただし下記のイラスト完成品質までは未達であり、すべてのカードが完成品になったわけではない。ユーザーが方向性を了承した参考デザインに合わせ、必ず「生きた食べ物 × 歴史・芸術・人物モチーフ」を絵として描き込む。完成品の基準：
- 実体あるオリジナルのキャラクターイラスト（人物・食べ物・衣装・ポーズ・表情を含む）。絵文字を中央に置くだけでは不可。
- N/Rでもキャラクターを主役としたカードとして魅力的な絵を制作。
- SSR はオリジナルの豪華な箔・光沢・額装で、絵と背景がまとまった作品にする。URはさらに例外的なフルアートや専用背景を持つ。
- 品質基準としてまず「SSR きらめきオムライス姫（卵ドレス、王冠）」「SSR 北斎・大波の和菓子（波を操る和菓子）」「R ケチャップオムライス（ケチャップのマントの冒険家）」の3枚を実際の絵で制作・レビューしてから大量展開。
- 参考にしたカードゲーム固有のキャラクターや既存のカードのレイアウトをコピーしない。ホログラムや箔、キラカードの“質感”のみ再解釈。
- レア別背景をCSS再利用するアーキテクチャは維持しつつ、SSR/UR等の特別カードはキャラと背景を個別に組み合わせることを認める。

## 2026-10-11 カード描画初期実装

- 共通背景と前景は分離するアーキテクチャを実装。`card-illustrations.js` をカードのベクター前景の入口とし、`game.js` で全カードに合成する。
- 最優先の3枚「きらめきオムライス姫」「ケチャップオムライス」「北斎・大波の和菓子」に個別の造形を作成した。ニュートンりんごとおこめちゃんも個別、他は共通の食べ物素体＋装備・装飾・モチーフ差分の初期描画。
- **現時点で作画の質感は先に承認された画像参考（高精細なカードイラスト）にまだ届いていない。** 専用の最終イラストアセットに差し替えることを前提とする。絵の品質を改善する際も、キャラID・背景データ・ガチャデータ・レベルを変更しない。
- アプリのヘッダー・導線など全体UIのデザイン調整は、主要機能の開発が揃った段階にまとめて実施。

### 技術設計
- `card-layer-manifest.js`：3枚の静的なアセットの対応表。キャラIDは従来どおりで、Firestoreのゲームデータ仕様は不変。
- `game.js`：カードの背景→ホロ素地・反射→下SVGフレーム→透過WebPキャラ→上SVGフレーム→光沢の順にDOM要素を重ね、名称・分類・レア・所持レベルはHTMLテキストを使う。
- `style.css`：Rはホロをなくし緑系の薄い背景・細い額。SSRは専用背景・前後フレーム・淡い反射を持つ。画面全体のデザイン変更はまだ行わない。
- 残りのキャラクターは従来のSVG仮イラストを一時的に表示。後でアセット追加・マスタに差し替える仕組み。ブラウザの画像読込に失敗した場合も旧SVGで表示できるようにする。
- `sw.js` に新モジュール・画像・SVGをキャッシュしてオフライン表示に対応。
- 透過WebPの上に名前やレア度の文字を焼き込まない。画像の外形は作画素材、枠と背景とテキストは個別に保守。
- 追加ガチャ、家族プロフィール、Firestoreコイン・ゲームデータは変更しない。

### 見栄えの品質チェック
初期3枚の読み込み・重ね合わせをブラウザで検証し、次の点を確認したら量産に進む。
- R：背景が穏やか、枠が簡素、ホロが見えず、キャラが主役
- SSR いちか：卵・衣装・冠が読み取れ、ハートとピンクゴールドが上品に重なる
- SSR 北斎：波・和菓子・筆が読み取れ、金と藍の前景がキャラを隠しすぎない
- 画面幅320pxとPC幅、一覧カードと大きいガチャ結果で文字の見切れがない
- イラストの品質は引き続き改善可能。今回の実装で「アート面の最終承認」が済んだとはみなさない

- 全体画面のデザイン調整は引き続き機能完成後に行う。

## 2026-10-11 Webアプリで直接確認する5レイヤー比較画面

ユーザーが求めるのは「完成カード画像の画像生成」ではなく「既存のWebアプリでの多層合成」である。
`/p/jun/?dev=1` → ごほうび → 動作確認モードON で、アプリ内の `#layerLab` に3枚の**実際の合成結果**を表示する。

- 比較対象は現時点で高品質な透過キャラWebPが揃っている **R ケチャップオムライス、SSR きらめきオムライス姫、SSR 北斎・大波の和菓子**。すでにあるキャラ素材を再利用する「レイヤー構造の品質検証」であり、新しい3キャラの完成を意味しない。
- 表示要素：ホロ下地 → 背景 → 背景だけのホロ → 下SVGフレーム → 透過キャラWebP → 上SVGフレーム → 反射 → HTMLのレア度・名前。
- 各層の表示／非表示スイッチと、ホロ強度スライダーを設ける。Rのホロはなし。CSS/画像素材は独立して編集可能。
- 本番のゲームデータや抽選処理への書き込みをしない。URLは管理者認証ではなく開発画面へのリンクである。
- **マンゴー王子・ニュートンりんご・ゴッホのひまわりパンの簡易SVGキャラは完成絵ではない。** 当該3体を完成品質と誤認して量産しない。まずは透過キャラ素材の品質を確保してから、既存の5レイヤー機構に組み込む。
- 全体UIの最終調整は機能完成後。

## 2026-10-11 レア度5段階の実カード比較とSSR方針

- `/p/jun/?dev=1` の「ごほうび」→「動作確認モード」→「N → UR：レア度5段階・実装比較」に、以前と違う5体を表示。キャラクターと背景・ホロ・下フレームSVG・上フレームSVGは個別アセット。レイヤーON/OFFとホロ強度スライダー付き。
- N：`rice_n`「おこめちゃん」、薄い紙色・最小限の枠・無ホロ。
- R：`mango_r`「マンゴー王子」、鮮やかな配色・緑系R装飾枠・無ホロ。Nとの差は背景色、フレーム、衣装の存在で示す。
- SR：`newton_apple_sr`「ニュートンりんご」、青銀の学者枠と薄いパール反射。
- SSR：`vangogh_bread_ssr`「ゴッホのひまわりパン」、ひまわり金枠と密度の高い虹色印刷ホロ。**SSRは実在の華やかなキラカードに近い、かなり強い光沢でよい**。
- UR：`secret_rinpa_ur`「宗達の千年黄金おこめ」、専用の濃色背景・虹色金箔・光の演出。URの名前や存在は未所持の通常図鑑に出さず、開発画面だけで比較。
- ユーザーの最終的な作品制作方針：**N/R/SR はキャラ＋共通の背景／前後SVGフレーム／ホロのパーツ合成を主力にする。SSR（11種類）とUR（3種類）は枚数が少ないため、完成カード・専用イラストの画像生成を許容する。** 必ずしもSSR/URまで5レイヤーで統一する必要はない。
- `game.js` のカードレンダラーは、従来の独立レイヤーのほか、manifest の `fullArt` を指定する**フルアートモード**を追加。フルアートの場合も名前・レア度・レベルのHTML表示は動的に保持する。生成素材は原則、文字やレア度バッジを画像に焼き込まない。
- **未完了**：この比較のSSR/UR画像は現時点では個別SVGイラストによる試作。見本のように細部まで描き込んだ生成フルアート自体はまだ画像アセットとしてGitHubに配置していない。現行のホロ密度と高精細アートの品質は別にレビューする。品質承認前に全カードを量産しない。
- これらは見た目のみの変更。抽選率、コイン、所持枚数、Firestore保存仕様には影響なし。
