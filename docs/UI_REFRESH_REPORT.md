# UI刷新・確認記録（2026-10-13）

## 実施内容

参考画像の木目・クリーム色・淡いグリーン・コーラルを基準に、共通の配色、角丸、ボタン、パネル、余白を追加。ホーム、ヘッダーの実残高、下部ナビゲーションを刷新した。既存の食事記録、図鑑、ガチャ、スタンプ、家族チャット、設定・履歴・バックアップへの導線は維持。

ホームのクエストは既存の達成処理と登録・休止・再開をそのまま使い、現在活動中の習慣に対する進捗を表示する。食事は1回で達成する既存仕様のまま。報酬欄は実際の所持券・無料ガチャ状態・連続日数・10/100連権利を表示し、架空の通貨・家具報酬は追加していない。

所持カードのプレビューは既存のカード描画・拡大・裏返しを再利用し、最大4枚。所持内容が同じならDOMを維持する。未取得URはプレビューにも出さない。既存カード画像・62ID・排出率・保存スキーマ・Firebaseルールは変更していない。

## おへやの構造と素材

`room-view.js` は静止背景を表示する独立したWeb Component。背景と空の重ね合わせ領域を同じ表示座標に置き、将来の箱庭コンポーネントへの置換やキャラクター・家具の重ね合わせに備える。今回、位置情報・家具操作・解放報酬・箱庭のデータベース・3Dエンジンは追加していない。

**専用の室内背景は既存素材にない。** 既存の木のテラス `assets/cards/scenes/scene-r.webp` と同一内容のWebPを仮背景 `assets/ui/room-placeholder.webp` に使った（114,500バイト）。画面にも準備中と表示。参考画像全体の貼り付けやSVGによる室内の再構築は行っていない。完成した室内用WebPを追加すれば、背景URLの差し替えで更新できる。

## 確認した画面サイズ

Chromiumで以下を確認。幅760px以上は左約52%・右約48%の2カラム、それ未満は同じDOMを1カラムへ再配置する。

| ビューポート | 構成 | 確認結果 |
| --- | --- | --- |
| 320 × 568 | 1カラム | 背景→記録→クエスト、全画面で横はみ出しなし |
| 390 × 844 | 1カラム | 記録ボタンが初期画面内、下部ナビ、カード拡大・裏返し |
| 667 × 375 | 1カラム | 横画面でスクロール・画面移動、横はみ出しなし |
| 768 × 1024 | 2カラム | iPad縦相当、右側各パネル・操作導線 |
| 820 × 1180 | 2カラム | iPad縦相当、文字・ボタンの横はみ出しなし |
| 1024 × 768 | 2カラム | iPad横相当、クエスト→記録→報酬→カード |
| 1180 × 820 | 2カラム | iPad横相当、下部ナビとスクロール |
| 1440 × 1000 | 2カラム | PC、左背景と右パネル群・一覧 |

ホーム以外にも食事・カード・ガチャ・スタンプ・家族・設定・メニューへ移動して確認。390、768、1024、1440pxではスクリーンショットも確認した。これはブラウザのビューポート確認であり実機テストではない。

## 回帰確認

- `node --test tests/*.test.mjs`：既存4テストファイルすべて通過。保存・同時更新・報酬重複防止・連続日数・一度限りの10/100連・移行・カードID/確率・キャッシュを確認。
- 3プロフィールの390px：タイマー開始→一時停止→再開→保存、手入力、同日食事による報酬重複防止、習慣登録・達成、進捗と実残高の更新、再読み込みでの保持を確認。
- 390px／1280px：未所持N〜SSRの60枠・UR秘匿、SSR金枠、拡大・裏返し、NEW初回のみ、10/100連と使用済み権利の再読み込みを確認。
- 上記操作中のJavaScript例外0件。横スクロールなし。家族チャットの入力・参加導線を維持し、本番家族への検証投稿は行っていない。Firebaseの保存処理とルールは変更していない。
- 起動時のカード画像要求0件、未表示図鑑のDOM生成0枚。ホームで所持カードがある場合だけ最大4枚を描画し、コインのみの更新ではカードDOMが同一であることを確認。
- Service Worker v37：起動用28ファイルだけを事前取得、画像は要求時にキャッシュ。新しい背景もキャッシュ優先で再利用する。背景画像の負荷は114.5KB追加のみ。全カードの一括取得は再導入していない。画面外のホームカードのホロも停止する。
