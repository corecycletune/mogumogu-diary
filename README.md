いちか・じゅんちゃん・さとばぁばが食事時間を記録する、iPhone/iPad向けPWAです。

## クエストとガチャ（2026-10-13・現行）

「できた！」は確認してから保存。クエストを1件でも達成すると、その日のごほうびガチャを1回引けます。複数達成しても回数は増えず、翌日への持ち越し・新しい券の付与はありません。ログインだけでは解放せず、既存の券・コイン・所持カード・コイン報酬・連続記録報酬は維持しています。

[PWAをホーム画面に追加する方法（iOS / Android）](pwa-guide.html)。

## UI刷新（2026-10-13）

ホームは木目・クリーム色・コーラルのゲームUI。幅760px以上は左右2カラム、それ未満は上下1カラム。ナビはホーム・カード・ガチャ・スタンプ・メニューに整理し、既存の記録・スタンプ・家族・設定は維持。おへやは独立した静止背景コンポーネントで、専用素材がないため既存テラスWebPを仮表示しています。

[変更・回帰確認・残課題](docs/UI_REFRESH_REPORT.md)。カードID・画像・ガチャ確率・報酬・保存形式は変更していません。

## 食事記録の表示（更新版）

- タイマー利用時は現在時刻から朝（05:00〜10:59）・昼（11:00〜15:59）・夜（それ以外）を仮選択。選択は変更可能。
- おやつは時間計測なしでワンタップ記録。履歴には「時間なし」と表示。通常の食事時間集計、スタンプ、連続記録、食事ボーナス、協力スタンプには算入しません。
- 記録後、食事画面の「最近の記録」に自動表示。全件は「きろく」から確認。
- 記録ごとに「端末に保存・同期待ち」「Firebase同期済み」「端末に保存（未連携）」などを表示。Firebaseに接続している表示だけで個別の同期完了とは判定しません。
- **重要：おやつの時間なし記録をクラウド保存するには、Firestoreルールを [firestore.rules](./firestore.rules) の最新版に置き換えて再公開してください。** 変更前のルールでは0秒の間食は拒否されます。

## アカウントとDB保存

ユーザーID（半角英数字・_、3〜24文字、大文字小文字は同一）とパスワード（10文字以上）で登録・ログインします。IDを内部の配信不能アドレスへ一意に変換し、Firebase Authenticationのパスワード認証を利用します。実際のメールアドレスは不要で、パスワード・認証トークンをFirestoreや公開ファイルに保存しません。メールでのパスワード再設定はありません。ログイン後の設定で現在のパスワードを使って変更できます。

- `users/{uid}` は本人だけが読めるプロフィール。`progress/game` と `progress/quests` にコイン・カード・習慣・達成日・10/100連権利を保存します。
- 食事は `users/{uid}/meals`、参加グループの一覧は `users/{uid}/groups`。グループ参加と個人の進行は独立しています。
- DBの認証・復元完了前は操作を開始しません。エラー時に端末内の新規残高へ切り替えません。食事の「保存しました」はDB書き込み成功後に表示します。
- ブラウザを替えたりPWAを削除・追加し直した後も、同じID・パスワードでDBの記録を読み戻します。端末内キャッシュはUIDごとに分離します。
- 旧プロフィールの選択・新規登録時の引き継ぎは廃止。旧URLは共通 `/p/app/` に移動します。ログイン後の既存UIDデータは保持します。
- 食事JSONの書き出しは引き続き食事専用です。完全バックアップではありません。
- グループチャットはUIDで識別し、ログインIDを表示。個人進行は `families` に保存しません。

既存プロジェクト `mogumogu-diary` / `(default)` / STANDARD / `asia-northeast1` を使用します。`firebase.json` の `auth` は旧匿名認証を残したままパスワード認証を有効にします。管理者が `firebase deploy --only auth,firestore:rules --project mogumogu-diary` を実行します。公開は従来どおりGitHub Pages（main / root）です。

認証用の管理者資格情報・サービスアカウント・ユーザーのパスワードをリポジトリに入れないでください。残高と抽選は既存のクライアント主導方式を維持しており、サーバーでの不正対策への変更は含みません。

## ゲーム試作（Firebase同期・ガチャ・図鑑）

**仕様の正本（SSOT）は [docs/GAME_DESIGN_SSOT.md](./docs/GAME_DESIGN_SSOT.md) です。** とくに「高品質のキャラ透過画像」「N/R/SRの5レイヤー合成」「SSR/URのフルアート許可」「背景面のホロ」という美術仕様を必ず確認してください。技術的な表示成功は作画の完成を意味しません。食事記録機能は従来どおり利用できます。

- **1日1回無料ガチャ**：本人のクエスト達成日に利用可能。同じ日の2回目はFirestoreトランザクションで拒否。
- **コイン・ガチャ券の保存**：`users/{uid}/progress/game` に保存。別端末でも同じIDで同期します。
- **インセンティブ**：ログイン10コイン/日、ごはん1回目20・2,3回目各10コイン/日（おやつは対象外）。連続3日+30コイン、7日+1券、14日+2券、30日+3券。追加ガチャ100コイン/回。
- **抽選率**：N72%, R20%, SR6%, SSR1.75%, UR0.25%。URはアプリ内では未発見時に表示もカウントもしません。独立抽選なので500回で必ず当たるわけではありません。
- **図鑑**：62キャラクター（オムライス、日本の芸術家、海外の芸術家、日常食、秘密枠）。キャラと背景は独立。重複枚数1/2/4/7/11でLv.1〜5。
- **表現**：共通CSSホログラム・カード枠をレアごとに再利用。一部のSSR/URは特殊背景を指定。現在、**完成済みの透過WebPキャラクター3体だけを表示**し、それ以外はキャラクター欄を空欄にしています。未承認の簡易SVGキャラ5ファイルとSVG自動生成プログラムは2026-10-11にGitHubから削除しました。N/R/SRは高品質な独立イラスト＋背景・前後SVGフレーム等の合成、SSR/URは豪華な専用フルアートも許容します。
- **履歴**：1キャラにつき所持枚数を保持し、抽選履歴は直近25件のみを保存。古い履歴が消えてもカードは消えません。

### 利用開始時に必須：Firestore ルールの再公開

ゲーム用の `/games/` 保存領域は以前の食事記録のルールにはありません。**[firestore.rules](./firestore.rules) の全文を Firebase Console → Firestore Database →「ルール」に貼り直し、必ず「公開」してください。** GitHubにファイルがあるだけではFirebase運用環境のルールは更新されません。更新前はゲーム画面に `permission-denied` 等が表示されます。

UID方式を使います。adminの作成とルールの公開順序は [ADMIN_RELEASE.md](./docs/ADMIN_RELEASE.md) を参照。

### セキュリティ上の制約

初期版は自宅用・非課金のクライアントゲームです。Firestoreトランザクションで同時操作の整合性を守りますが、ブラウザに抽選率・キャラクター表・抽選処理を配布するため、**技術的なユーザーによる内容閲覧や残高の改ざんを完全には防ぎません**。外部公開・商用利用前にサーバー側（Cloud Functions等）で抽選と報酬を検証する構成への移行が必要です。


### 管理者専用の動作確認モード

`roles/{UID}.admin == true` をサーバーから確認した管理者だけが `/p/app/?dev=1` でテストガチャ・レイヤー比較・SSR試作を利用できます。`junsakata0720` は一般の生活記録用です。ID文字列だけでは管理者になりません。adminのテスト状態はページ内メモリのみで、本番の記録・カード・残高を変更しません。

管理者本人によるアカウント作成、役割設定、ルール公開、リリース確認は [docs/ADMIN_RELEASE.md](./docs/ADMIN_RELEASE.md) にまとめています。
