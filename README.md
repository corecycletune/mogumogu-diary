# もぐもぐ日記 / mogumogu-diary

いちか・じゅんちゃん・さとばぁばが食事時間を記録する、iPhone/iPad向けPWAです。

## 食事記録の表示（更新版）

- タイマー利用時は現在時刻から朝（05:00〜10:59）・昼（11:00〜15:59）・夜（それ以外）を仮選択。選択は変更可能。
- おやつは時間計測なしでワンタップ記録。履歴には「時間なし」と表示。通常の食事時間集計、スタンプ、連続記録、食事ボーナス、協力スタンプには算入しません。
- 記録後、食事画面の「最近の記録」に自動表示。全件は「きろく」から確認。
- 記録ごとに「端末に保存・同期待ち」「Firebase同期済み」「端末に保存（未連携）」などを表示。Firebaseに接続している表示だけで個別の同期完了とは判定しません。
- **重要：おやつの時間なし記録をクラウド保存するには、Firestoreルールを [firestore.rules](./firestore.rules) の最新版に置き換えて再公開してください。** 変更前のルールでは0秒の間食は拒否されます。

## Firebase Consoleの初期設定（必須）
Webアプリの設定は `firebase-sync.js` に登録済みです。

1. Firebase Console → **Authentication** → **始める** → **ログイン方法** → **匿名** を有効にして保存。
2. Firebase Console → **Firestore Database** → **データベースを作成** → **本番環境モード** → リージョン選択 → 作成。テストモードにしないでください。
3. Firestore Database → **ルール** タブに、リポジトリ直下の [firestore.rules](./firestore.rules) の内容を**全文コピー**し、**公開**してください。
4. ブラウザでじゅんちゃんのページへ移動し、「きろく」→「家族と同期」→「新しい家族グループを作る」を押す。
5. 表示された24文字の家族コードを、いちか・さとばぁばの端末に**個別に**伝える。
6. それぞれの端末で自分のプロフィールページ →「きろく」→「家族と同期」→「家族コードで参加」を押す。

家族コードは144ビットの乱数です。**知っている人なら家族として参加できるため、公開したりSNSに貼らないでください。**
ログイン画面・パスワードは不要ですが、内部ではFirebase匿名認証を使って端末を識別します。端末のブラウザデータを消去すると認証状態が失われます。その場合は家族コードで再登録してください。

### データ保存の方針
- 食事記録はまずIndexedDBに保存し、接続後は自動的にFirestoreへ送信。
- Firebaseの初回接続時、既存の端末内記録を同じIDで移行。
- オフラインや同期エラー時の未送信記録は端末内に残し、オンライン復帰や「同期を再試行」で再送を試みます。
- 端末内データの保全のため、定期的に「きろく」→「バックアップ」から書き出し推奨。
- 家族内では登録メンバーが3人分の食事記録を読み取り可能。編集・削除は登録プロフィールの記録のみ許可。
- 共通の端末で複数プロフィールを使う場合は匿名認証IDが共有されるため、初期版では**1端末1プロフィール**を推奨。

### 注意事項
- Firestoreの Security Rules を設定する前にクラウド保存を試しても、デフォルトのアクセス拒否となります。
- Firebase Web API Keyは公開設定ですが、サービスアカウントの秘密鍵ではありません。管理者権限はFirestore Rulesで管理します。
- 公開リポジトリやコミットに家族コード・食事記録・サービスアカウント秘密鍵を入れないでください。
- Firestoreのルールによる制限は過度な利用の完全防御ではありません。公開サービスに拡張する際はApp Check等の追加対策が必要です。

## ゲーム試作（Firebase同期・ガチャ・図鑑）

仕様・確定事項の詳細は **[docs/GAME_DESIGN.md](./docs/GAME_DESIGN.md)** に保存しています。食事記録機能は従来どおり利用できます。

- **1日1回無料ガチャ**：家族のFirebaseに接続した本人だけが利用可。同じ日の2回目はFirestoreトランザクションで拒否。
- **コイン・ガチャ券の保存**：各プロフィールの `families/{familyCode}/games/{profile}` に保存。別端末でも、同一プロフィールのゲーム状態を同期。
- **インセンティブ**：ログイン10コイン/日、ごはん1回目20・2,3回目各10コイン/日（おやつは対象外）。連続3日+30コイン、7日+1券、14日+2券、30日+3券。追加ガチャ100コイン/回。
- **抽選率**：N72%, R20%, SR6%, SSR1.75%, UR0.25%。URはアプリ内では未発見時に表示もカウントもしません。独立抽選なので500回で必ず当たるわけではありません。
- **図鑑**：62キャラクター（オムライス、日本の芸術家、海外の芸術家、日常食、秘密枠）。キャラと背景は独立。重複枚数1/2/4/7/11でLv.1〜5。
- **表現**：共通CSSホログラム・カード枠をレアごとに再利用。一部のSSR/URは特殊背景を指定。現在のキャラは絵文字による**仮アート**で、オリジナルイラストは今後追加するものです。
- **履歴**：1キャラにつき所持枚数を保持し、抽選履歴は直近25件のみを保存。古い履歴が消えてもカードは消えません。

### 利用開始時に必須：Firestore ルールの再公開

ゲーム用の `/games/` 保存領域は以前の食事記録のルールにはありません。**[firestore.rules](./firestore.rules) の全文を Firebase Console → Firestore Database →「ルール」に貼り直し、必ず「公開」してください。** GitHubにファイルがあるだけではFirebase運用環境のルールは更新されません。更新前はゲーム画面に `permission-denied` 等が表示されます。

各プロフィールの匿名ユーザー認証・家族グループ登録も必要です。ゲームデータはそのプロフィールが所属する家族グループ内に保存されます。別の端末で匿名IDが変わると同じプロフィールとして自動参加できない場合があるため、現段階でのマルチデバイス再登録は未対応です。

### セキュリティ上の制約

初期版は自宅用・非課金のクライアントゲームです。Firestoreトランザクションで同時操作の整合性を守りますが、ブラウザに抽選率・キャラクター表・抽選処理を配布するため、**技術的なユーザーによる内容閲覧や残高の改ざんを完全には防ぎません**。外部公開・商用利用前にサーバー側（Cloud Functions等）で抽選と報酬を検証する構成への移行が必要です。


### じゅんちゃん専用の動作確認モード

`/p/jun/?dev=1` を開いたときだけ「ごほうび → もぐもぐガチャ」に「🧪 動作確認モード」の開閉パネルがあります。チェックをONにすると、無料ガチャボタンが**テストガチャ**になり、Firebaseの接続状態、同日上限、コイン残高に関係なく何度でも抽選をプレビューできます。レア度を N / R / SR / SSR / 隠しカードから固定して見た目を確認できます。検証用の重複枚数・レベルアップもページ内メモリだけで計算します。**テスト結果はクラウドに送信されず、本物の図鑑、コイン、ガチャ券、無料ガチャ使用枠には影響しません**。モード解除・ページ再読み込みでテスト結果は消去されます。

※ 機能は「じゅんちゃんのURL」かつ `?dev=1` の時のみ表示しますが、**そのURLを開いた人を本人認証で識別しているわけではありません**。運用上の開発者用UIです。正式な管理者権限が必要になった場合は別途認証・認可設計を行います。

本番ガチャが無効な場合は、まず「きろく」→「家族と同期」が**接続済み**か確認してください。PCとiPhoneは別ブラウザのため、PC側でまだ家族グループに参加していない可能性があります。ゲームのデータの権限エラー（`permission-denied`）が表示されたらFirebaseの`firestore.rules`最新版をConsoleの「ルール」に貼り付けて「公開」してください。**テストガチャ成功だけでは本番Firebaseが正常とは判定できません。**
